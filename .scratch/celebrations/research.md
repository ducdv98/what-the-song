# Round-win celebrations — research and proposal

**Scope (5 October 2026).** First-party product pages, support docs, and developer docs only. This is a design proposal, not a claim that every competitor uses each suggested effect. A Round has a variable Stage ladder; Score depends on Stage position and Tier, and Streak spans Topics ([CONTEXT.md](../../CONTEXT.md)). The shipped look is a Vietnamese gig poster, with a cream result card, ink stamp, coral accents, and existing one-shot result motion ([DESIGN.md](../../DESIGN.md)).

## What other games reward

|---|---|---|

| **Heads Up!** | The publisher's listing describes tilting down for a correct guess and up to pass, immediately drawing another card; the group supplies much of the energy. [Warner Bros. listing](https://apps.apple.com/us/app/heads-up/id623592465) | Listing does not establish a specific screen animation or haptic pattern. |

| **Vietnamese Đuổi Hình Bắt Chữ / Bắt Chữ** | WePlay VN's published listing emphasizes the playful answer reveal and says in-game reward points can buy help. A separate app's publisher describes consecutive streaks; another lists repeat guesses and a leaderboard. [WePlay VN listing](https://play.google.com/store/apps/details?id=vn.weplay.batchu&hl=vi), [2026 app listing](https://apps.apple.com/vn/app/%C4%91u%E1%BB%95i-h%C3%ACnh-b%E1%BA%AFt-ch%E1%BB%AF-2026/id1320564113), [B ADAM listing](https://play.google.com/store/apps/details?id=xuanbac.namtao.duoihinhbatchu&hl=vi) | “Đuổi Hình Bắt Chữ” names several separate apps. Their publisher text/screens do not reliably establish one universal celebration animation. |

**Pattern:** Give every Match a clear success state; show *why* the Score was earned; reserve a larger treatment for early Stage, difficult Tier, first-ever win, or Streak milestones. Persistent records and the next action matter more than a long spectacle. This is an inference from the cited products, not a shared industry rule.

## Options for Bạn có tài mà

Costs below are **incremental compressed JS estimates**, excluding CSS, fonts, and any animation assets. “CSS 0” means ~0 KB added JS and at most a few hundred bytes of CSS per effect, not a zero-size download. All effects sit on the finished result, never over a Clue or answer field; text and the Next action remain immediately available. The existing result stamp can be a common base, with **one** option selected per won Round. Every motion variant has a still equivalent in the table; honor `prefers-reduced-motion: reduce` rather than merely shortening its duration.

| # | Name, visual and trigger | React/CSS approach; cost | Reduced-motion equivalent; phone budget |
|---|---|---|---|
| 1 | **Ink hit** — a bold “Chính xác!” stamp lands beside the Subject title. Baseline for any win, especially later Stage. | Existing result stamp + one transform/opacity entry; **CSS 0**. | Show stamp immediately; one element, ≤320 ms. |
| 2 | **Score reel** — earned `+Score` counts up once beside a plain Stage/Tier explanation. Any win, weighted toward medium Stage. | React `requestAnimationFrame` over ~350 ms from 0 to the already-final Score; **CSS/JS 0 library KB**. | Show final `+Score` immediately; update one text node at most once per frame and cancel on unmount. |
| 3 | **Setlist sweep** — actual unlocked Stage marks ink in left-to-right, ending at winning Stage. A first-half Stage win. | CSS `transition` on existing Stage strip, derive count from Round data; **CSS 0**. | Final markers immediately; animate ≤5 marks, never invent five if ladder differs. |
| 4 | **Ticket tear** — small printed “Stage 1” ticket slides out beside Score. First-Stage win on the *actual* ladder. | Pseudo-elements and transform; **CSS 0**. | Static ticket; avoid clipping long Vietnamese Subject titles. |
| 5 | **Coral burst** — 8–12 short coral/yellow rays radiate from the result stamp, like poster ink. Early Stage win or high Score. | CSS pseudo-elements or a tiny inline SVG; **CSS 0**. | Static starburst; animate a single wrapper, not each ray. |
| 6 | **First show** — “Chiến thắng đầu tiên” ticket appears with a small check and won-Round count 1. First recorded win ever (including Warm-up). | Conditional React label + CSS entrance; **CSS 0**. | Static keepsake; do not imply Stage 1 for a Warm-up win. |
| 7 | **Streak spark** — Streak number gains a small flame/star accent; no mascot needed. Streak 3, with variant at 5. | CSS accent + one numeral entry; **CSS 0**. | Static icon and number; Streak remains readable without color. |
| 8 | **Streak banner** — a narrow “3/5/10 trận liên tiếp” ribbon unfurls above Score; milestone only. | CSS `clip-path`/scaleX on one banner; **CSS 0**. | Full banner immediately; keep under ~350 ms and no takeover. |
| 9 | **Tier seal** — hard/expert/impossible Tier gets a distinct printed seal, with one brief glint along its edge. Any win in those Tiers. | CSS border/pseudo-element; **CSS 0**. | Static seal; do not use glitter particles or color alone to encode Tier. |
| 10 | **Encore confetti** — 20–40 paper rectangles pop near the result and clear quickly. First-Stage expert/impossible win, or Streak 10. | Dynamically import `canvas-confetti`, set `disableForReducedMotion: true`, bounded `particleCount`, origin near card; **~4.4 KB gzip** for pinned v1.9.4 browser build. [API](https://github.com/catdad/canvas-confetti), [artifact](https://cdn.jsdelivr.net/npm/canvas-confetti@1.9.4/dist/confetti.browser.min.js) | Static “Đỉnh!”/achievement seal; one burst, ≤1 s, cancel on unmount and avoid full-screen repeat. |

The **rare banner, seal, or confetti** should represent recognition, not extra points. Score remains the existing Stage/Tier formula. A bespoke Lottie mascot is an optional future direction, but Lottie light is roughly **46 KB gzip** and full roughly **76 KB gzip**, plus animation JSON/assets; its SVG-only light player omits effects/expressions. That cost is hard to justify for the first version. [Lottie Light](https://github.com/airbnb/lottie-web/wiki/Lottie-Light), [light build](https://cdn.jsdelivr.net/npm/lottie-web@5.13.0/build/player/lottie_light.min.js), [full build](https://cdn.jsdelivr.net/npm/lottie-web@5.13.0/build/player/lottie.min.js). Sizes are measured pinned distribution artifacts, so production bundling may differ.

## Variety and integration rule

1. On a won Round, compute flags from the resolved Round: `winningStageIndex`, `stageCount`, Tier, prior `won`, and **new** global Streak. Treat first half as `winningStageIndex < ceil(stageCount / 2)`; this works for variable ladders. Avoid treating elapsed wall time as speed: this game rewards Stage, not a timer.
2. Choose **one main option** by priority: first-ever win → Streak 10 → first-Stage expert/impossible → Streak 5/3 → hard+ Tier → first-half Stage → ordinary win. Milestone copy may accompany the selected effect as a quiet static label. Keep #1 as the common result status, and select one optional variation from eligible effects #2–#10.
3. Use a small shuffled bag per intensity pool (ordinary: 2/3/5; early: 3/4/5; first-ever win: 6; milestone: 7/8; hard Tier: 9; rare: 9/10). Before drawing, remove the last **two** effect IDs when the pool permits, at minimum the immediately previous ID. Persist recent IDs per player/device across Topics (e.g. local storage); if storage is unavailable, keep the history in memory. Choose once at the won-Round transition and hold that choice in result state so re-rendering/reopening the same result does not replay or change the effect.
4. Escalate by **area and rarity**, not by stacking layers: ordinary effect stays inside the result card; early/hard win adds ticket/seal; Streak 10 or first-Stage expert/impossible gets a single confetti burst. Keep Next tappable during motion. The result currently auto-opens a Meme dialog when enabled; delay or dismiss the effect before that dialog, or show the Meme only after the result has been visible, so the two celebrations do not compete. Reuse the existing Meme pool's immediate-repeat avoidance where possible.

## Sound, haptics, access and performance

- **Sound:** Ship with **no new sound**. [DESIGN.md §8](../../DESIGN.md) explicitly makes the sample audio the sole cue and excludes applause/clicks. If the design direction changes later, offer a separate default-off celebratory sound setting, stop the Clue first, keep a very short cue, and trigger audio only after a user gesture; browsers restrict autoplay. [MDN Web Audio](https://developer.mozilla.org/en-US/docs/Web/API/Web_Audio_API/Best_practices)
- **Haptics:** Optional, default-off single ~10–20 ms `navigator.vibrate` tap for a won Guess and perhaps `[15, 35, 15]` for a rare milestone, only on a supported browser after a direct gesture. Never depend on it for meaning: the API has limited availability and needs user activation. Do not vibrate when reduced motion is requested or a Meme dialog is taking focus. [MDN Vibration API](https://developer.mozilla.org/en-US/docs/Web/API/Vibration_API), [MDN `vibrate()`](https://developer.mozilla.org/en-US/docs/Web/API/Navigator/vibrate)
- **Accessibility:** Show the text outcome, Score, winning Stage, Tier, and Streak independent of animation. Announce the result politely **once**, not each particle/number; decorative layers use `aria-hidden`. Respect the user's `prefers-reduced-motion` by replacing nonessential motion with a still state. [MDN reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/%40media/prefers-reduced-motion), [WCAG technique C39](https://www.w3.org/WAI/WCAG22/Techniques/css/C39)
- **Mobile:** Favor a few transform/opacity animations on the result card; avoid layout-triggering frame-by-frame style changes and persistent loops. Cap any canvas burst and clean it up before navigating. [MDN animation performance](https://developer.mozilla.org/en-US/docs/Web/Performance/Guides/Animation_performance_and_frame_rate)
